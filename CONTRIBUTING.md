# Contributing

Use the [Trello board](https://trello.com/b/b0cLTB64/diarockets-kanban) for task ownership and progress. Read the [team workflow](docs/gearth/team-workflow.md) before starting a branch.

Each new task gets a focused branch and a pull request linked to its Trello card. Name branches `<type>/<description>` and PRs `<type>: <short description>` using `feat`, `fix`, `test`, `docs`, or `chore`; see the team workflow for examples. Do not use a `codex/` branch prefix. Use the PR template to record the relevant checks and remaining work. Keep code review and integration evidence with the card; finish it after its acceptance criteria are met.

See [README](README.md) and the applicable runbook for launch and verification commands. The expanded world and its scheduling, compute, observer, decision metrics, banking and analytics changes are integrated into `main`; start new work from the current main branch.
